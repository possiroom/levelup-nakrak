[재현된 게임 문제]

1. 높음 — 기억공간 캐릭터 그래픽 깨짐.
T2/T3/T4에서 A가 다른 이미지 조각처럼 표시되고, 주인의 외형도 위치에 따라 이상하게 보이는 경우가 있다. 주인공과 겹치지 않을 때도 발생.
포트레이트 원본 수입 상태는 모두 1752×1752, 최대 4096, 압축 없음, Bilinear로 확인했다. 원본 포트레이트가 작게 수입된 문제와 별개로 월드 캐릭터 렌더링 이상이 재현된다.
원인은 확정하지 않았으며 공용 흑백 머티리얼의 스프라이트 텍스처 처리 확인이 필요하다.
캡처: T2-A-not-overlapped.png, Tutorial_T3_VaseBreak-A-not-overlapped.png, Tutorial_T4_BroochMissing-A-not-overlapped.png.

2. 높음 — 사람과 겹칠 수 있고, B는 겹친 위치에서 상호작용된다.
T2/T3/T4의 A/B 위치에 플레이어가 들어갈 수 있다. 물리 충돌 검사를 통과하는 경로와 실제 컨트롤러 이동으로 확인.
T2 B는 (4,3)에서 위를 보면 반응이 없고 B와 같은 칸 (4,4)에서 위를 보면 증거 제시 창이 열린다. 재검토에서도 동일.
S3에서도 A/B/C/조수의 칸에 들어갈 수 있으며, 조수 자리까지 실제 이동하여 겹침을 확인했다.
캡처: T2-overlap-A.png, Exhaustive/S3-assistant-overlap.png.

3. 중간 — 어두운 T3의 도자기 파편 조사 누락.
S3 이후 재방문한 T3에서 파편 앞 (-4,-1), 아래 방향 상호작용에 반응이 없다. T4 같은 위치에서는 T4_Fragments_First 대사와 조사가 동작한다.
T3 장식장 조사는 정상이다. T3 조사 전체가 막힌 상황은 아니다.
캡처: Recheck/Tutorial_T3_VaseBreak-fragments-confirm.png, Recheck/Tutorial_T4_BroochMissing-fragments-confirm.png.

4. 중간 — 카운터 시계 조사 무반응.
T2 (-2,2), 위 방향의 실제 상호작용이 Counter Watch에 맞지만 대사/획득 모두 없다. 재검토 동일.
지급하려는 evidence-pocket-watch가 Retired 상태여서 보상 단계에서 중단된다. 아이템 제거가 의도여도 조사 지점의 무반응은 남는다.
캡처: counter-no-response.png. 기록: Recheck/recheck-runtime.txt.

5. 중간 — 증거 제시 성공 목록에 실제 제시한 것과 다른 이름 표시.
B에게 장식장 흔적을 제시하여 성공하면 왼쪽 목록에는 일자 드라이버가 나온다. 1/3 숫자는 맞다.
실제 제시한 아이템 대신 보유한 인정 증거 중 먼저 발견된 항목을 표시한다.
캡처: successful-item-label.png. 기록: runtime-review4.txt.

6. 중간 — S3의 흰 원이 별도 NPC로 남아 이전 대사를 재생한다.
S3 중앙의 흰 원은 S#3이라는 오브젝트이며 Circle 스프라이트와 NPC가 활성화되어 있다.
직접 걸어가 상호작용하면 Assets/Scripts/New Folder/Text_S#3/DialogContainer/Start.asset에 연결된 예전 대사 S부터 재생한다.
첫 대사는 '...대충 상황은 알겠군.'이며 A/B/주인의 설명과 조수의 거짓말 관련 대사가 이어진다. 정상 S3 진입 대화 이후에도 별도로 다시 시작할 수 있다.
흰 원의 외형과 이전 대사 연결이 의도인지 확인 필요.
캡처: Recheck/S3-circle-dialogue.png. 기록: Recheck/room-audit2.txt, Recheck/S3-circle-story.txt.

7. 조건부 중간 — 손상된 저장 파일 복원 실패 후 로딩/조작 잠금이 풀리지 않는다.
존재하지 않는 아이템 ID가 들어간 QA용 저장 파일을 사용했다. 일반적인 정상 저장에서 발생한 문제는 아니다.
파일 읽기 검증은 통과하지만 InventoryModel.Restore에서 ArgumentException이 발생한다. 실제 ChangeSession 경로 실행 후 menu.loading=True, IsBlockingGameplay=True, IsRestoringSession=True가 남았다.
따라서 이런 형식의 손상/호환 불가 파일은 실패 안내 후 복귀하지 못하고 조작이 막힌 상태로 남을 수 있다.
기록: Recheck/bad-save-runtime.txt. 사용자 실제 저장 파일은 바꾸지 않았다.

8. 낮음 — 저장 슬롯 장소명이 PrototypeScene으로 표시된다.
실제 T2/T3 등 현재 장소가 제목에 드러나지 않는다. 내부 additiveScenes는 저장되며 복원은 정상.
캡처: save.png.

9. 낮음/의도 확인 — 첫 기억공간 출구에 제한 설명이 없다.
첫 방문에서 탈출을 막는 것은 의도일 수 있으나, 출구 상호작용에 안내가 없다.
T0 방 출구의 '브로치를 챙겨 보석함에 넣어 두자' 안내와는 다른 항목이다. T0 출구 안내는 실제 이동 검사에서 정상 확인.
기획서의 첫 기억공간 출구 안내와 최신 의도를 비교해 확인 필요. 재방문 탈출 취소/확인은 정상.
기록: runtime-review.txt의 EXIT first=True no dialog.

[사소한 관찰 및 확정하지 않은 항목]

10. 세로 화면 720×1280에서 메뉴 아이템 이름 5개가 잘린다.
기한이 지난 전당포증, 떨어진 보석함, 브로치가 담긴 보석함, 일자 드라이버, 전화기 사용 흔적.
나머지 검사한 가로/4:3 화면에서 메뉴 텍스트 넘침은 검출되지 않았다. 대사 본문은 6개 크기 모두 넘침 0.
세로 화면을 지원할 계획이 없다면 낮은 우선순위다.
캡처: Exhaustive/layout-720x1280-Menu.png.

11. 방 가장자리의 큰 검은 여백과 방 일부 잘림.
방 경계의 카메라 프레이밍 의도 확인 필요. 캐릭터 그래픽 깨짐과는 별도다.
캡처: T2-A-not-overlapped.png 등.

12. 저장 백업 파일은 있어도 자동 복구하지 않는다.
정상 .bak가 있는 수동 저장의 본 파일을 깨뜨렸을 때 TryReadManual은 실패하며 .bak를 읽지 않는다.
자동 복구가 요구사항인지 확인할 항목. 정상 저장 복원 실패로 분류하지 않는다.
기록: Recheck/recheck-runtime.txt의 SAVE BACKUP.

13. 콘솔/빌드 경고.
기존 플레이 중 Event System 중복 및 ConditionToEvent 없음 경고가 관찰됐다. 재검토에서 활성 EventSystem은 1개였고 실제 입력 중복은 확인하지 못했다.
빌드 경고 3개는 TutorialScene1Cutscene.openingCameraSize 미사용 1개와 URP Light2D 셰이더의 벡터 축약 2개다. 빌드는 성공했다.
그래픽 없는 실행에서 나오는 Null GPU/Unsupported Shader 메시지는 해당 검사용 실행 방식에 따른 것으로 일반 GPU 실행의 게임 결함으로 세지 않았다.

14. 연속 저장 스트레스 중 일회성 IOException.
최초 실험에서 파일 교체 오류가 한 번 나왔다. 이후 작업 폴더/임시 폴더에서 20회 저장과 추가 순환 검사는 정상 통과했다.
반복 재현되지 않아 확정 결함에서 제외하고 관찰 기록만 남긴다.
기록: Exhaustive/exhaustive-runtime.txt, Exhaustive/save-rotation-confirm.txt, Recheck/recheck-runtime.txt.

[앞선 보고 정정 및 검사 도구 오류 제외]
- '전화기 사용 흔적 아이콘이 브로치'라는 이전 판단을 철회한다. 원본 Telephone.png와 캡처를 다시 확인했으며 구형 전화기 이미지다.
- UI 임시 해상도 항목을 정리하다 발생한 Invalid index 반복과 디버거 연결 확인 창은 내 검사 도구 오류다. 게임 결함에서 제외한다. 임시 6개 항목을 제거하고 기존 선택으로 복구했으며, 디버깅 활성화는 하지 않았다.
- 초기 증거 매트릭스에서 일반 아이템을 중요 아이템 탭에서 찾다가 실패한 것은 검사 준비 오류다. 전체 탭으로 수정한 matrix-runtime.txt의 180개 확인은 모두 통과했다.
- T0 첫 물리 이동 검사의 시간초과는 출구 안내 대사를 검사기가 넘기지 않아 생긴 것이다. 안내에 응답하도록 검사기를 고친 room-audit2.txt에서는 실제 이동·획득·포장이 모두 통과했다.
- runtime-review2.txt의 상자/엔딩 실패는 불완전한 테스트 상태 때문이며 자연 진행 엔딩 재검사로 해소됐다.

[검증의 한계]
모든 가능한 플레이를 문자 그대로 무한히 전수 검사한 것은 아니다. 명시된 유한 조합과 주요 정상/실패/반복 경로를 검사했다.
입력은 실제 게임 컨트롤러·상호작용·UI 처리 코드 실행을 중심으로 확인했다. Editor에 큐로 보낸 키가 구형 Input에 전달되지 않아 물리 키보드/마우스의 모든 조합은 검증하지 못했다.
독립 실행 빌드는 빌드 성공과 그래픽 없는 기동만 확인했다. 일반 그래픽 모드의 전체 엔딩, 실제 전체화면 전환, 기기별 입력, 오디오 청취는 미검증이다.
기획서는 참고 자료로 사용했으며, 이후 사용자 메시지에서 변경된 연출은 최신 요청을 우선했다.
